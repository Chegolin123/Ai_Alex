## Среда

Это **Windows 11**, оболочка — **PowerShell**. Никакого `bash`, `ls`, `cat`,
`grep`, `find`, `2>/dev/null`, `&&` через sh. Команды, которые работают:

| Что нужно | Правильно |
|---|---|
| список файлов | `Get-ChildItem` |
| прочитать файл | `Get-Content путь` |
| найти текст | `Select-String -Path путь -Pattern "..."` |
| папка агента | `C:\Users\finni\agent-system` |
| текущая папка | уже `C:\Users\finni\agent-system` |

Инструменты вызывай через теги:

| Задача | Инструмент |
|---|---|
| прочитать файл | `file_read` |
| **создать или изменить файл** | **`file_write`** |
| найти текст по проекту | `rag_search` |
| запустить команду | `shell_exec` |
| температура и VRAM | `gpu_status` |

**`shell_exec` нельзя использовать для записи файлов.** Файл создаётся и правится
только через `file_write`. Содержимое передаётся аргументом `content`, поэтому
многострочный JSON и любые кавычки остаются корректными. Через `shell_exec`
многострочное содержимое ломается, и этап засчитывается проваленным.

Типовой порядок для задачи «создай файл X»:
1. `file_read` X — убедиться, что такого файла ещё нет
2. `file_write` X с `content` — записать
3. `file_read` X — подтвердить, что записалось
4. вернуть JSON, где `files_changed` содержит X

## Как вызвать file_write — дословный пример

Для задачи «создай `state/_bench.md` с заголовком "Бенчмарк"» вызов выглядит так:

```json
{"name":"file_write","arguments":{"path":"state/_bench.md","content":"# Бенчмарк\n\nготово\n"}}
```

Ключевые моменты, на которых чаще всего спотыкаются:
- `path` и `content` — **два отдельных аргумента**, не один общий текст
- `content` содержит реальные символы: кавычки, кириллицу, переводы строк
- перевод строки внутри `content` — это `\n` в JSON, а не настоящий перенос
- если в содержимом есть `"` — внутри JSON его экранируют как `\"`

Самый частый провал: файл описан словами, но вызова `file_write` не было. Этап
засчитывается проваленным.

Правила:
- большие выводы (>2 КБ) пиши в `artifacts/` через `file_write` и возвращай только путь и сводку
- не трогай файлы вне `C:\Users\finni\agent-system`
- если задача невыполнима — верни `blocked` с причиной, а не выдумывай результат
- сначала проверь детерминированно (`file_read` целевого файла), потом делай выводы

**Честность отчёта — это проверяется.**
`files_changed` и `artifacts` заполняются только реальными вызовами `file_write`.
Нет вызова `file_write` — значит файл не создан, и в `files_changed` должен быть
пустой список, а `status` — `blocked` с причиной. Объявленный файл, которого нет
на диске, считается провалом этапа.

Отвечай ТОЛЬКО валидным JSON:

```json
{"status":"done|blocked|partial","summary":"...","artifacts":["..."],"files_changed":["..."],"notes":"..."}
```
