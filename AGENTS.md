# ALEX — правила работы на этой машине

Ты работаешь как агент системы ALEX на Windows 11, PowerShell, локальная модель
Ornith-1.5-9B (контекст 131072, целиком в VRAM). Рабочая папка:
`C:\Users\finni\agent-system`. Модель через `http://127.0.0.1:8080/v1`.

## Главное правило: shell только через защиту

Твой инструмент terminal — это **git-bash (MSYS)**, а не PowerShell. В нём
работают `ls`, `cat`, `grep`. PowerShell-команды (`Get-ChildItem`,
`Test-Path`, `Select-String`) там **не работают**.

Любую команду, которая должна выполняться как PowerShell, запускай
**исключительно** так:

```
C:\Users\finni\agent-system\bin\alex.cmd run "<командация на PowerShell>"
```

`alex.cmd` вызывает `powershell.exe` сам, поэтому всё внутри кавычек —
это синтаксис PowerShell: `Get-ChildItem`, `Test-Path`, `Select-String`,
`$env:PATH`.

Прямой вызов terminal для чего-либо, кроме `alex.cmd`, `python` и запуска
Hermes, считается ошибкой. `alex run` проверяет команду по списку запрещённых и
отменяет работу при перегреве. Коды: `0` успех, `3` заблокировано,
`4` термозащита.

Для чтения файлов shell не нужен вовсе: есть `read_file` и `search_files`.
Для поиска по системе — `alex rag`.

## Порядок любой задачи

1. **Прочитай, не гадай.** Файлы читай через `read_file`, поиск — `search_files`
   или `alex rag "<запрос>"`. Не описывай содержимое файла, которого не открыл.
2. **Сплань** 2–4 этапа, у каждого: действие и критерий проверки.
3. **Выполни**, до 3 попыток на этап.
4. **Проверь детерминированно**: файл существует, ключ в JSON на месте, команда
   вернула 0. Если проверить нечем — скажи об этом прямо, а не объявляй успех.
5. **Отчитайся** одной строкой: сделано, проверено, что осталось.

Лимиты: 3 попытки на этап, 20 шагов на задачу, одна и та же ошибка дважды подряд —
остановиться и объяснить причину.

## Подробности — в skills

Тела skills не в контексте постоянно, они подгружаются по вызову
`skill_view(<имя>)`. Вызывай, когда нужно:

| Skill | Когда |
|---|---|
| `alex-orchestrator` | порядок работы, разведка, планирование, проверка |
| `alex-self-improve` | цикл улучшений, приоритет дефектов, модель изменений |
| `alex-system` | железо, сервер модели, RAG, версии, расписание |

## Посредник

Ярлык **Посредник.cmd** запускает Hermes с ролью посредника: он принимает задачи,
докладывает состояние проектов и **задаёт вопросы, накопленные автономными
агентами**. Роль приходит через `HERMES_EPHEMERAL_SYSTEM_PROMPT`, поэтому
действует только в той сессии — обычный Hermes остаётся обычным.

Агенты работают по часам и спросить человека не могут. Всё, что их блокирует,
они пишут в очередь: `alex.cmd questions`, ответить — `alex.cmd answer <id>
"текст"`, отвечает человек.

Свои вопросы в очередь ставит и сам посредник: `alex.cmd ask "<вопрос>"`.

## Как узнать, улучшает ли система сама себя

```
alex.cmd progress
```

Даёт честный вердикт и код возврата: `0` — улучшает, `1` — нет. Разделяет два
вопроса, которые легко спутать: цикл **запускается** сам по расписанию и цикл
**меняет** систему. Запускаться он может каждый час и при этом не улучшать ничего.

Если пользователь спрашивает «улучшает ли себя система» — вызывай `progress` и
перескажи вердикт дословно, включая «нет». Не сглаживай.

## Как смотреть идущую работу

Твой terminal возвращает результат **только когда команда закончилась**, и вывод
обрезается. Поэтому ход процесса в твоём окне не виден в реальном времени.

Чтобы следить за живой работой:

- `alex live` — идёт ли сейчас цикл самоулучнения (JSON, одна проверка)
- `alex watch` — поток транскрипта: отметки фаз и живые размышления модели
- транскрипт лежит в `logs/improve-thinking.log`

Запуск с размышлениями: `alex.cmd improve 1 --thinking`. Обычный `alex improve 1`
безопаснее: размышления съедают бюджет токенов, из-за чего ответ иногда не
дописывается.

Если пользователь просит «покажи, что происходит» — сначала `alex live`, потом
запусти и предложи смотреть через `alex watch` в отдельном окне.

## Особенности модели — не борись с ними

- **Reasoning-модель.** Структурные ходы идут с `reasoning_effort: none`, иначе
  она съедает весь бюджет токенов на размышления и возвращает пустой ответ.
- **JSON-only она не держит.** Выдаёт валидный объект и дописывает мусор, поэтому
  схема навязывается грамматикой llama.cpp.
- **Tool calling нативный**, текстовый `[Tool Call]` не встречается.

## Среда

Твой terminal — git-bash. Читать и искать лучше родными инструментами
`read_file` / `search_files`, а не командами оболочки.

Windows 11. Пути Windows пишутся с обратными слэшами и работают:
`C:\Users\finni\agent-system`. Bash-пути вроде `/c/Users/...` тоже есть, но
в отчётах и командах для `alex run` используй Windows-вид.

Файлы вне `C:\Users\finni\agent-system` не трогай без прямой просьбы.

Железо: 8 ГБ VRAM, модель занимает почти всё. Перед нагрузкой — `alex gate`.
Пока модель работает, игры не запустятся (ярлык «Игровой режим»).
